# Quill MCP server — design

Date: 2026-09-28 · Status: awaiting approval

## Goal

Let AI tools outside Claude Code — Cursor, Claude Desktop, claude.ai, and any
other MCP client — use Quill correctly without installing anything from Quill
first. One URL pasted into the tool's settings connects it.

Inside Claude Code, apps already get the rules file and the `quill-components`
skill via `@quill/agent-rules`; this server is for everywhere else. The shadcn
MCP that apps also run drops Quill's docs, use-when and not-for lines (recorded
2026-09-08 against shadcn 4.21.0), so it cannot fill this gap.

## Decisions (agreed with Ryan, 2026-09-28)

- **Hosted, not local.** A route on the existing Vercel site, not an npm package.
- **Read-only, public, no auth.** Everything it serves is already public
  (registry, `llms.txt`, `/usage/*.md`).
- **Dependencies added:** `mcp-handler@^2`, `@modelcontextprotocol/server@^2`,
  `zod@^4`. `mcp-handler` 2.x requires the SDK v2 packages and zod ^4.2 (its
  README); `@modelcontextprotocol/sdk` 1.x is the wrong pairing.

## Architecture

- **One file:** `src/app/mcp/route.ts`, exporting `createMcpHandler(...)` as
  `GET` and `POST`. Stateless (MCP spec 2026-07-28, with the SDK's fallback for
  2025-era clients), so no session store or Redis.
- **Public URL:** `https://www.quilldesignsystem.com/mcp/` — with the trailing
  slash. `next.config.ts` sets `trailingSlash: true` (Storybook needs it), so
  `/mcp` answers with a 308 redirect, which some MCP clients will not follow.
  Every place the URL is published uses the slash form.
- **Tool logic lives in `src/mcp/tools.mjs`**, plain functions with no MCP
  types, so the node test runner can call them without Next. `route.ts` only
  registers them.
- **Data is read from source, not from generated copies:**
  - `ALL_USAGE` from `src/usage/index.mjs` — 107 guides (56 components,
    51 patterns).
  - `registry.json` — tells Quill items (installed by URL) apart from stock
    shadcn primitives (installed by name), and supplies each block's
    `meta.intent`, `meta.use_when`, `meta.not_for`.
  - `renderUsageDocs(u, { format: 'markdown' })` and `renderNotFor(u)` from
    `src/usage/render.mjs` — the same renderers `build-usage.mjs` uses for
    `public/usage/*.md`, so `get_component` returns the published guide verbatim.
  - `renderFoundations`, `renderPrinciples` (`src/usage/foundations.mjs`) and
    `renderThemeDocs` (`src/usage/theme-docs.mjs`) — the same renderers behind
    DESIGN.md and `llms.txt`.

  Because the route imports the sources, a usage edit reaches the MCP on the
  next deploy with no new build step.

## Tools

All tools return markdown text.

| Tool | Input | Returns |
|---|---|---|
| `find_component` | `task` (string) | Up to 5 matches: name, kind, summary, use-when. |
| `get_component` | `name` (string) | Full usage guide + the exact install command. |
| `get_setup` | — | Theme install, the five themes and four accents, shipped-tokens-only rule. |
| `get_foundations` | `topic?`: `type` \| `spacing` \| `effects` \| `principles` | That section, or all four. |

**`find_component` ranking:** lower-case word overlap between the task and each
guide's name, summary, use-when, alternatives' `when`, and (for blocks)
`meta.intent` / `meta.use_when`, ignoring a short stop-word list. Words that hit
`meta.not_for` subtract. Ties break by name. With no score above zero it returns
"no Quill component fits" plus the principle that says to compose from
primitives, never an invented name.

**`get_component` install line:** registry items (except `quill`,
`agent-rules`, `check`, `example-*`) →
`npx shadcn@latest add https://www.quilldesignsystem.com/r/<name>.json`; every
other guide is a stock primitive → `npx shadcn@latest add <name>`. An unknown
name returns up to 3 nearest real names (edit distance), never a fabricated one.

**`get_setup`** derives themes and accents from `ALL_MODES` / `accentNames()`;
nothing is typed by hand (`theme-enumeration.test.mjs` would catch it anyway).

**Server instructions** (shown to the agent on connect): call `find_component`
before building UI; prefer a Quill block over hand-building; follow each
guide's Do/Don't rules; use only shipped tokens.

## Documentation

- README: a "Connect your AI tool" section — the URL, a Cursor/Claude Desktop
  JSON snippet (`{"url": "…/mcp/"}`), and the `npx -y mcp-remote <url>` form for
  stdio-only clients.
- `llms.txt`: one line naming the MCP URL (generated by `build:llms`, so the
  generator changes, not the output).

## Testing

`scripts/mcp.test.mjs`, picked up by `npm run test:tokens`:

- every one of the 107 guides resolves through `get_component`;
- Quill blocks get the URL install, primitives the name install;
- `find_component("confirm deleting an account")` ranks `alert-dialog` first;
- an unknown name (`alertdialog`) suggests `alert-dialog`;
- `get_setup` names exactly the themes in `ALL_MODES` and the accents from
  `accentNames()`;
- `get_foundations` returns non-empty text for each of the four topics, and all
  four when no topic is given;
- `get_component` output equals the matching `public/usage/<name>.md` body.

Plus `npx tsc --noEmit`, `npm run lint`, and an end-to-end check before merge:
`npm run dev`, then list tools and call each one against
`http://localhost:3000/mcp/` with a real MCP client, and confirm `/mcp`
(no slash) redirects rather than erroring.

## Shipping

Minor version bump (new feature) + CHANGELOG entry; regenerate with
`npm run build:check && npm run build:registry && npm run build:llms`; PR →
green `Lint · types · tests · build` → merge; the release bot tags. Connecting
Cursor / Claude Desktop to the live URL is Ryan's step after deploy.

## Out of scope

Code checking (`@quill/check` covers it), token lookup by value, auth, usage
analytics, semantic/embedding search. Each can be added later if a real need
shows up.
